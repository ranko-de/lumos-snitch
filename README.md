# Lumos & Snitch — A Split-Screen Quidditch Chase

משחק דפדפן תלת־ממדי לשני שחקנים מקומיים במסך מפוצל: כל שחקן רוכב על מטאטא באצטדיון קווידיץ׳ ומנסה לתפוס את הסניץ׳ הזהוב. כל שחקן יכול להחשיך את חצי המסך שלו — בחושך הסניץ׳ זוהר ומשאיר שובל, באור קל יותר לנווט.

**סגנון:** גרפיקה מצוירת (cel-shading עם קווי מתאר), אלפי צופים מונפשים ביציעים, ופסקול מקורי שנוצר בקוד: ואלס בתיבת נגינה במסך הפתיחה, ואלס תזמורתי בזמן המשחק, גרסה מהירה עם תופים בהארכה ופנפרה בסוף. יש גם קריאות עידוד מהקהל, זמזום של הסניץ׳ כשמתקרבים אליו, ושוש כשעוברים דרך טבעת.

> **פרויקט מעריצים לימודי ולא רשמי.** אינו קשור, ממומן או מאושר על ידי בעלי הזכויות של עולם הארי פוטר. כל הגאומטריה, הטקסטורות והצלילים נוצרים בקוד (פרוצדורלית) — אין מודלים, מוזיקה, דיאלוגים או לוגואים מהסרטים או מהספרים.

נבנה עם Three.js, TypeScript ו־Vite. אפליקציה סטטית: אין backend, אין מפתחות API ואין תלות ב־localhost בזמן משחק.

## התקנה והרצה

דרוש Node.js בגרסה 20.19 ומעלה (מומלץ 22).

```bash
npm install          # בפעם הראשונה גם יוצר package-lock.json — כדאי לשמור אותו ב־git

npm run typecheck    # בדיקת טיפוסים
```

## משחק במקלדת (בלי חומרה)

כל המשחק, כולל שני ה־easter eggs, עובד במקלדת. במסך הבחירה יש:
- **Two players — keyboard:** שני שחקנים על מקלדת אחת, במסך מפוצל.
- **One player — keyboard:** שחקן יחיד במסך מלא. אפשר לטוס גם עם WASD וגם עם החצים. במשחק יחיד יש 3 דקות לתפוס כמה שיותר סניצ׳ים (שלוש תפיסות = ניצחון). את דמבלדור אפשר להפעיל רק כשיש יריב.

| פעולה | שחקן 1 (שמאל) | שחקן 2 (ימין) |
|---|---|---|
| פנייה | `A` / `D` | `←` / `→` |
| צלילה / טיפוס | `W` / `S` | `↑` / `↓` |
| בוסט מהירות | `F` | `K` |
| בלימה + פנייה חדה (החזקה) | `G` | `L` |
| יום / לילה | `R` | `O` |
| השהיה | `Esc` | `Esc` |

אובדן פוקוס של החלון מנקה את כל המקשים ועוצר את המשחק.

## חוקי המשחק

- עד 3 דקות. הראשון ששלוש תפיסות — מנצח מיד.
- נגמר הזמן: בעל יותר תפיסות מנצח; בשוויון — הארכה, התפיסה הבאה מנצחת.
- אחרי תפיסה הסניץ׳ נעלם ומופיע מחדש אחרי 3 שניות, רחוק משני השחקנים.
- **התפיסה אוטומטית:** מספיק לעוף קרוב מספיק לסניץ׳ (כ־4 מטרים) בלי מכשול ביניכם.
- כפתור התפיסה הוא עכשיו **בוסט מהירות**: לחיצה אחת = בוסט של כשנייה וחצי, ואחריו צינון של כ־3.5 שניות. החזקת הכפתור לא יוצרת בוסטים חוזרים.
- **בלילה המטאטא איטי יותר** (כ־70% מהמהירות): קל יותר לראות את הסניץ׳, קשה יותר להשיג אותו.
- שני השחקנים מגיעים לסניץ׳ באותו צעד: הקרוב יותר זוכה; במרחק שווה — הסניץ׳ חומק משניהם.

**סודות קטנים** (לא מסומנים במשחק — רק רמזים):
- עופו אל תא השופטים (באמצע היציע הארוך). דמבלדור יצטרף אליכם למטאטא, וכשתתקרבו ליריב הוא יטיל עליו Crazy Broom ויחזור ליציע. פעם אחת לכל שחקן במשחק, עם צינון משותף.
- ומה קורה אם שני השחקנים בוחרים בחושך יחד?

## חומרה: שלושה micro:bit v2

| לוח | תפקיד | חשמל |
|---|---|---|
| `controller-p1` | שלט שחקן 1 | מארז סוללות (2×AAA) |
| `controller-p2` | שלט שחקן 2 | מארז סוללות (2×AAA) |
| `receiver` | גשר רדיו → USB | כבל USB **שמעביר נתונים** למחשב |

> כבלי USB רבים מעבירים רק חשמל. אם הלוח נדלק אבל לא מופיע ככונן `MICROBIT` במחשב — החליפו כבל.

הפרוטוקול מתועד ב־[docs/PROTOCOL.md](docs/PROTOCOL.md).

### צריבת הלוחות (MakeCode)

**הדרך הקלה:** בתיקייה [`firmware/hex/`](firmware/hex) יש קבצים מוכנים — `lumos-controller-p1.hex`, `lumos-controller-p2.hex` ו־`lumos-receiver.hex`. הורידו את הקובץ המתאים וגררו אותו לכונן `MICROBIT` של הלוח (או פתחו אותו ב־MakeCode ← **Import**).

לחלופין, לבנייה מהקוד:

לכל אחת משלוש התיקיות ב־`firmware/` יש `main.ts` ו־`pxt.json`.

1. פתחו את [makecode.microbit.org](https://makecode.microbit.org) ← **New Project**, ותנו שם (למשל `lumos-p1`).
2. עברו ללשונית **JavaScript** (למעלה באמצע).
3. מחקו את הקוד הקיים והדביקו את התוכן של `firmware/controller-p1/main.ts`.
4. הוסיפו את התוסף **radio** אם MakeCode מבקש (בדרך כלל הוא נטען אוטומטית).
5. חברו את הלוח ב־USB ולחצו **Download** (או העתיקו את קובץ ה־`.hex` לכונן `MICROBIT`).
6. חזרו על התהליך עבור `controller-p2` ועבור `receiver`.

ההבדל היחיד בין `controller-p1` ל־`controller-p2` הוא השורה `const PLAYER_ID = …`. מומלץ לסמן את הלוחות במדבקה (1, 2, R).

בהדלקה השלט מציג לרגע את מספר השחקן ואז נשאר כבוי — זה מכוון: חיישן האור משתמש במטריצת הלדים, ולכן אין אנימציות בזמן משחק. המקלט מציג סמל ✕ קטן ומהבהב בפינה כשמגיעים נתונים.

### אחיזת השלט

- החזיקו את הלוח שטוח, הלדים למעלה, הקצה עם מחבר ה־USB רחוק מכם.
- אגודל שמאל על **A** (בוסט מהירות), אגודל ימין על **B** (החזקה: האטה קלה + פנייה חדה ומהירה — מחזיקים B תוך כדי הטיה לצד).
- **לילה:** קפלו אצבע מורה מעל הקצה העליון וכסו את **השורה העליונה של הלדים** — האגודלים נשארים על הכפתורים.
- הטיה ימינה/שמאלה = פנייה; הטיה קדימה = צלילה; אחורה = טיפוס.

### חיבור והפעלה מהשלטים (בלי כיול)

נדרש **דפדפן שולחני שתומך ב־Web Serial: Chrome או Edge** (לא Firefox/Safari, ולא בטלפון).

1. הדליקו את השלט (או שניהם) וחברו את המקלט ב־USB.
2. **סגרו כל תוכנה אחרת שתופסת את הפורט** — חלון MakeCode עם „Show console”, Arduino Serial Monitor, PuTTY וכו׳.
3. **בפעם הראשונה בלבד:** לחצו **Connect micro:bit** במסך הפתיחה ובחרו את המקלט. הדפדפן זוכר את ההרשאה, ובפעמים הבאות המשחק מתחבר לבד כשהוא נטען או כשמחברים את המקלט.
4. מכאן הכול נשלט מהשלטים:
   - **מסך הפתיחה:** לחיצה על **A** בשלט פותחת את מסך „Who is playing?”.
   - **הצטרפות:** כל שחקן לוחץ **A** בשלט שלו. שחקן אחד = משחק יחיד; שניים = מסך מפוצל.
   - **התחלה:** **B** בשלט של שחקן שהצטרף.
   - **דילוג על התרגול:** החזיקו **A + B** יחד לרגע.
   - **מסך התוצאות:** **A** = משחק חוזר, **B** = חזרה לתפריט.

**אין צורך בכיול:**
- האחיזה הניטרלית נמדדת אוטומטית בזמן הספירה לאחור (3-2-1), אז פשוט החזיקו את השלט בנוחות.
- סף האור והחושך מסתגל לבד לתאורת החדר לפי הקריאות האחרונות.
- כיוון ההטיה מוגדר מראש לפי האחיזה המתוארת למעלה. אם הטיפוס והצלילה הפוכים, סמנו Invert בתפריט ההשהיה.
- מי שבכל זאת רוצה כיול ידני מוצא אותו בתפריט ההשהיה (**Recalibrate controllers**).

אם שלט מפסיק לשדר באמצע משחק, המשחק נעצר. כשהשלט חוזר הוא ממשיך לבד; אפשר גם **Reconnect receiver** או **Switch Player N to keyboard**.

> **סאונד:** הדפדפן מאפשר צליל רק אחרי לחיצה כלשהי בעמוד (עכבר או מקלדת). אם המשחק התחבר לבד ואין צליל, לחיצה אחת בכל מקום בעמוד מפעילה אותו.

### תקלות נפוצות

| תקלה | פתרון |
|---|---|
| כפתור micro:bit אפור / „Web Serial is not available” | השתמשו ב־Chrome או Edge במחשב. העמוד חייב לרוץ ב־https או ב־localhost (GitHub Pages מתאים). |
| הלוח לא מופיע ברשימת הפורטים | כבל USB של חשמל בלבד; החליפו כבל. נסו פורט USB אחר. |
| „Could not open the port” | תוכנה אחרת מחזיקה את הפורט — סגרו את MakeCode console / Serial Monitor ונסו שוב. |
| „Waiting for controller…” | סוללות חלשות, שלט כבוי, או קבוצת רדיו שונה בין הקבצים (`RADIO_GROUP`). |
| השליטה הפוכה | כיילו מחדש (שלבי „ימינה” ו„קדימה” קובעים את הכיוון), או סמנו Invert בתפריט ההשהיה. |
| יום/לילה מהבהב | כיילו במקום עם אור יציב, וכסו את השורה העליונה כולה. |
| „micro:bit (weak signal)” | קרבו את השלטים למקלט; הרחיקו אותו ממקורות הפרעה. |
| ביצועים איטיים | בתפריט ההשהיה: **Low quality** (מוריד רזולוציה; צפיפות קהל ושמיים מופחתת בטעינה הבאה). |

## העלאה ל־GitHub ופרסום ב־GitHub Pages

1. צרו repository חדש ב־GitHub (למשל `lumos-snitch`).
2. מתיקיית הפרויקט:
   ```bash
   npm install                     # יוצר package-lock.json
   git init
   git add .
   git commit -m "Lumos & Snitch"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```
3. ב־GitHub: **Settings ← Pages ← Build and deployment ← Source: GitHub Actions**.
4. ה־workflow ב־`.github/workflows/deploy.yml` רץ בכל push ל־`main`: התקנה, typecheck, בדיקות, בנייה ופריסה.
5. המשחק יהיה זמין בכתובת `https://USERNAME.github.io/REPOSITORY/`.

### נתיב הבסיס (Vite base)

- ברירת המחדל ב־`vite.config.ts` היא base יחסי (`./`), שעובד מכל תת־נתיב — גם ב־GitHub Pages וגם ב־`npm run preview`.
- אפשר לכפות נתיב מוחלט: `VITE_BASE=/my-repo/ npm run build`.
- ה־workflow מגדיר אוטומטית `VITE_BASE=/<שם ה־repository>/` (או `/` עבור repository בשם `USERNAME.github.io`). שום שם משתמש או repository לא מוקשח בקוד.
- כל הנכסים נוצרים בקוד או נארזים ע״י Vite, כך שאין נתיבים מוחלטים שיישברו בתת־נתיב.

## מבנה הקוד

```
src/
  config.ts            כל ערכי הכוונון (מהירויות, רדיוס תפיסה, זמנים, צינונים…)
  strings.ts           כל הטקסטים של הממשק (באנגלית, במקום אחד לתרגום עתידי)
  app.ts               מסכים, מקורות קלט, לולאת האנימציה היחידה
  game/                סימולציה משותפת אחת: טיסה, סניץ׳, תפיסה, easter eggs, ניקוד
  input/               שכבת קלט אחידה: מקלדת, micro:bit, כיול
  serial/              Web Serial, פענוח NDJSON, פרוטוקול
  render/              Renderer אחד, canvas אחד, שתי מצלמות (viewport + scissor)
  audio/               צלילים מסונתזים ב־Web Audio (רק אחרי אינטראקציה)
  ui/                  HUD, מסכים, CSS
firmware/              controller-p1, controller-p2, receiver (MakeCode TypeScript)
tests/                 בדיקות יחידה
docs/PROTOCOL.md       תיעוד הפרוטוקול
```

עקרונות:
- **סימולציה אחת** בצעד קבוע של 1/60 שנייה; שתי התצוגות מציירות את אותו עולם.
- **מצב התאורה של כל תצוגה נכתב במלואו לפני כל מעבר רינדור**, כך שיום/לילה של שחקן אחד לא דולף לחצי השני.
- הקהל הוא `InstancedMesh` אחד; מצב הרוחות הוא uniform בשיידר — אין יצירת מודלים חדשים.
- delta time מוגבל אחרי השהיה או החלפת לשונית.

## בדיקות

`npm test` מריץ בדיקות ל:
- פענוח serial: שורות חלקיות, כמה שורות ב־chunk, קלט פגום, הגבלת buffer.
- שיוך חבילות לשחקנים, מספרי רצף, עטיפת מונים, לחיצה קצרה שלא נאבדת.
- תפיסה אוטומטית בקרבה; לחיצה אחת = בוסט אחד; צינון הבוסט; מטאטא איטי יותר בלילה.
- הכרעה בין שני ניסיונות תפיסה בו־זמניים (כולל תיקו).
- ניצחון מיידי בשלוש תפיסות, הארכה, סיום זמן.
- דמבלדור: מצטרף כשמתקרבים לתא, מכשף רק כשמתקרבים ליריב, משך הכישוף 5 שניות, חוזר הביתה, פעם אחת לשחקן, צינון משותף, הכרעה הוגנת.
- רוחות רק אחרי שנייה רצופה של חושך משותף, השהיית שחרור וצינון לצליל.
- כיול, hysteresis ו־debounce של האור, נתונים מיושנים → ניטרלי.
- איפוס מלא במשחק חוזר.
